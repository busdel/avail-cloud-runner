Everything on this platform is also one command away in your own environment - the same pipeline, the same leak-free validation protocol and the full comparison suite:

pip install avail-omics           # core: CPU-only
pip install "avail-omics[deep]"   # + neural & foundation meta-learners

avail-omics run-generic --data-root my_data --out results
avail-omics robustness  --data-root my_data --out results  # leak-free permutation
avail-omics sensitivity --data-root my_data --out results  # modality ablation
avail-omics figures     --out results

{{ icon('file','ic') }} Data format - information notes
metadata.tsv 
SampleID    Group    Age    Sex
S001        HC       71     M
S002        MCI      66     F
S003        PDD      74     M

Required: SampleID, Group (any class names). Optional: Age, Education, Sex.

features/stool16S.tsv (one file per layer) 
SampleID    Bacteroides    Prevotella    ...
S001        0.12           0.004
S002        0.09           0.010
S003        0.15           0.002

Rows = samples, first column = SampleID, remaining columns = features. Any tabular omics layer works; missing samples per layer are fine - availability flags handle them.

Optional compositional.txt: list one modality name per line (e.g. stool16S) for relative-abundance or count layers; those get a log/CLR transform. Unlisted layers are treated as continuous measurements. The pipeline logs every classification and reports disagreement with its automatic heuristic - nothing is transformed silently.

Imaging uploads: check Extract radiomics to add PyRadiomics features from T1 volumes (optional; runs where the radiomics tier is installed - server, cloud or your own computer).

Imaging uploads: include metadata.tsv plus, per subject, a 4D BOLD NIfTI named after the SampleID (e.g. sub-001_task-rest_bold.nii.gz) or a DICOM folder named sub-001. The runner and the free cloud extract Schaefer-100 connectivity features automatically (register to a template space, e.g. MNI, for the atlas to align). Large imaging cohorts: prefer the local runner - it processes your files on your machine with no upload (the web upload path is best for feature tables and small imaging tests; tunnel uploads are additionally capped near 100 MB by the network path).
